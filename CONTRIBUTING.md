# Contributing

Thanks for improving the roadmap. Keep changes focused, beginner-friendly,
defensive, and reproducible.

## Good contributions

- Correct technical inaccuracies.
- Improve explanations for beginners.
- Add authoritative documentation.
- Replace stale resources.
- Report broken links.
- Add safe exercises or project ideas.
- Improve navigation and accessibility.

## Workflow

1. Fork the repository.
2. Create a focused branch such as `docs/networking-dns`.
3. Make the smallest useful change.
4. Check Markdown links and headings.
5. Review terminology and safety boundaries.
6. Open a pull request describing the change and why it improves the roadmap.

## Resource acceptance standard

A new resource should have a clear purpose, appropriate difficulty, credible authorship, and a stable destination. Prefer official documentation and maintained educational projects.

Do not add:
- unauthorized-target instructions
- credential theft material
- malware intended for deployment
- personal data
- copyrighted material copied into the repository
- promotional spam

## Writing standard

Use:
- short paragraphs
- descriptive headings
- tables when comparison helps
- examples that teach concepts
- explicit prerequisites
- clear checkpoints

Avoid:
- unexplained jargon
- giant URL dumps
- claims of guaranteed employment
- "master cybersecurity in X days" language

## Pull request checklist

- [ ] Internal links checked
- [ ] External links verified
- [ ] No secrets or personal data
- [ ] Technical claims reviewed
- [ ] Safety boundaries preserved
- [ ] Markdown renders correctly
- [ ] New material has a clear place in the roadmap


For suspected vulnerabilities in this repository, follow [SECURITY.md](SECURITY.md).
Community expectations are in [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
